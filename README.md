# VIN-Twin

Русскоязычный MVP для кейса №2 АЛЛЮР: аналитика предоставленных тестовых данных и отдельная учебная VIN-симуляция. Стек: FastAPI, Python-симуляция, Next.js, TypeScript, Tailwind и SVG. Таблицы 01–02.10.2026 предоставлены как тестовые данные кейса; VIN, BOM и события симуляции синтетические. Проект не подключён к АЛЛЮР, MES, WMS или реальному оборудованию.

## Быстрый запуск

Нужны **Python 3.12** и **Node.js 22+** с npm. На macOS/Linux из каталога проекта:

На macOS с Homebrew установите нужную версию: `brew install python@3.12`. Установщик выбирает именно `python3.12`, независимо от версии команды `python3`. Можно указать полный путь: `VIN_PYTHON=/path/to/python3.12 bash scripts/install.sh`.

```bash
bash scripts/install.sh
bash scripts/dev.sh
```

Откройте **http://localhost:3000** — главная страница с описанием проекта. Аналитика завода — **http://localhost:3000/factory**, VIN-симуляция — **http://localhost:3000/dashboard**. API доступен на том же origin по `/api`. Первичная установка требует интернета, после неё расчёты, сценарии, VIN, объяснения и отчёты работают без внешней сети.

Можно запустить оба процесса одной командой после установки:

```bash
npm run dev
```

Она использует установленную `.venv` и запускает оба сервера; при необходимости переменные окружения задайте перед запуском. `scripts/dev.sh` дополнительно читает корневой `.env`.

### Windows / PowerShell

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r backend/requirements.lock.txt
npm ci --prefix frontend
npm run dev
```

### Production, локально

```bash
npm run build --prefix frontend
```

Терминал 1, из корня:

```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Терминал 2:

```bash
npm start --prefix frontend
```

### Docker Compose

```bash
docker compose up --build
```

Откройте http://localhost:3000. Backend не публикует отдельный порт наружу. Docker-конфигурация подготовлена, запуск Docker в среде разработки не проверен.

## Если установка оборвалась на Python 3.14

Ошибка `pyo3-ffi` / `pydantic_core` в этом наборе зависимостей означает неподходящую версию Python. Сообщение `No module named uvicorn` — следствие незавершённой установки.

Установите Python 3.12 и повторите `bash scripts/install.sh`. Обновлённый установщик сохраняет несовместимую `.venv` в `.venv-backup.XXXXXX/environment` и создаёт новую, затем устанавливает Python- и Node-зависимости. `bash scripts/dev.sh` и `npm run dev` проверяют готовность backend перед запуском.

## Страницы

- `/factory` — аналитическая панель по данным кейса: качество, оборудование, месячный план, сценарный калькулятор OEE, объяснения и отчёт.
- `/` — описание проекта: задача, принцип работы, разделы демо и границы модели. Работает без запроса к backend.
- `/dashboard` — интерактивный диспетчер смены.
- `/dashboard?scenario=delay` — демонстрация задержки поставки.
- `/dashboard?view=scenarios` — сравнение политик.
- `/dashboard?view=vin` — VIN-реестр.

Логотип в дашборде возвращает на главную.

## Возможности

- **Обзор:** факт/реконструкция на выбранное время, прогноз, план, недовыпуск, запасы A/B, ETA, схема шести ресурсов, загрузка, очереди, инциденты и рекомендация.
- **Временная шкала:** 08:00–16:00, воспроизведение, пауза, скорость, метка прогноза после демонстрационного «сейчас» 10:00.
- **Сценарии:** штатная смена, задержка поставки, отказ робота, оба сбоя; пользовательские задержка, начало и длительность сбоя, время решения и вклад автомобиля.
- **Три политики:** FIFO, срочная доставка, разрешённая перестановка. Можно применить действие только к сценарию и сбросить его.
- **VIN:** поиск, фильтры, маршрут, расписание, ожидания, завершение и сравнение с базой. На схеме по клику открываются пост и очередь.
- **Данные:** JSON-импорт с серверной проверкой, пример для скачивания; лента событий с повторяемым ID и воспроизведением получения обновления ETA в 10:00.
- **ИИ-диспетчер:** содержательные локальные ответы всегда доступны. Необязательный Gemini выбирает intent и fact_id, а итоговый текст с числами строится сервером по проверенным фактам.
- **Отчёт:** просмотр, копирование, скачивание TXT и печать. Формируется по тому же snapshot_id.
- **Интерфейс:** тёмная и светлая темы, клавиатурный фокус, Escape и ограничение фокуса в панелях, responsive-стили, reduced-motion, загрузка, ошибки сервера и пустой поиск. Внешние шрифты и скрипты не нужны.

## Проверенная модель

Смена 480 минут, 80 VIN, пустая линия, шесть последовательных ресурсов по 6 минут. Завершение ровно в 16:00 учитывается. Теоретическая мощность — **80**, штатный выпуск — **75**, план — **75**.

| Условия | FIFO | Доставка | Перестановка |
|---|---:|---:|---:|
| Штатная смена | 75 | 75 | 75 |
| Поставка +100 мин | 63 | 71 | 69 |
| Робот 40 мин | 68 | 68 | 68 |
| Оба сбоя | 63 | 68 | 68 |

На старте 48 A и 6 B. VIN-055…060 требуют B. Партия 40 A планируется на 12:30; +100 мин даёт 14:10. Комплект расходуется однократно при начале сборки-1. FIFO при задержке ждёт с 13:00 до 14:10.

Доставка перемещает ту же партию на min(ETA,13:20), стоимость 380 000 ₸. Позже 13:20 предложение недоступно. Если партия уже поступила к моменту решения, её прошлый приход не меняется. Перестановка стоит 90 000 ₸ и переносит VIN-055…060 после VIN-048; запрещена, если данные её не разрешают или затронутый VIN уже начал маршрут.

Робот недоступен с 10:30 на заданное число минут. Пересекающая сбой операция приостанавливается; незапущенная ждёт восстановления. Отказ — сценарное условие, не ML-прогноз.

**Спасено** = выпуск с действием − выпуск FIFO при тех же сбоях. **Условный эффект** = спасено × вклад − затраты. Вклад по умолчанию 650 000 ₸. При задержке доставка даёт +8 / 4 820 000 ₸, перестановка +6 / 3 810 000 ₸. В штатной смене рекомендовано бездействие; при обоих сбоях — перестановка.

## Архитектура

```text
Next.js UI → /api rewrite → FastAPI → engine.py
                                  → snapshot store
                                  → explanations.py → optional Gemini
                                  → report.py
JSON → models.py validation → event adapter → engine.py
```

- `backend/engine.py`: чистая детерминированная модель, доступность политик, инвентарь, расписание, состояния и кадры для схемы.
- `backend/models.py`: строгая проверка параметров, JSON и событий.
- `backend/data/`: набор, пример импорта и события отдельно от UI.
- `backend/main.py`: API, ограничение запроса, хранение снимков.
- `backend/explanations.py`: intent, проверка fact_id, Gemini с таймаутом и локальный fallback.
- `backend/report.py`: отчёт передачи смены.
- `frontend/app/`: интерфейс, SVG-схема, график, карточки, VIN, панели и типы.

Frontend не моделирует производство. Он выбирает рассчитанный Python-кадр, отображает операции и преобразует числа в координаты графика. Запросы симуляции отменяются; порядковый номер запроса не позволяет старому ответу заменить новый. Чат и отчёт проверяются по актуальному снимку перед отображением.

## API

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/health` | Доступность и режим объяснений |
| GET | `/api/state` | Демо-набор, события, источник и время |
| POST | `/api/simulate` | Параметры → полный снимок |
| POST | `/api/chat` | snapshot_id, question → intent, fact_refs, answer |
| POST | `/api/report` | snapshot_id, time → текст отчёта |

Пример:

```bash
curl http://localhost:3000/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"delay":100,"robot_minutes":0,"policy":"delivery","decision_time":120,"contribution":650000}'
```

`/api/simulate` также принимает `data` (формат `backend/data/import-example.json`), `events` и `received_until`. События с одним ID учитываются один раз. В UI воспроизведение начинает с 08:00 и доходит до 10:00, когда приходят обновление ETA и сценарное условие робота. Слайдер отражает реконструкцию состояния известного снимка; получение новых сведений показывается отдельно через воспроизведение событий.

Размер POST ограничен 256 КиБ. Чат — до 2000 символов. Входы проверяются на диапазоны и допустимые политики. Не хватает материала даже после партии — 422, а не отрицательный запас.

## Gemini

Без ключа ничего настраивать не нужно. При необходимости:

```bash
cp .env.example .env
```

Добавьте `GEMINI_API_KEY` в `.env` и запустите `scripts/dev.sh`. Ключ передаётся провайдеру только backend, через заголовок. Модель задаётся `GEMINI_MODEL` и зависит от доступа аккаунта; демонстрация не требует Gemini.

Таймаут — 4 секунды. Ошибки API, JSON, intent и fact_id переводят ответ на локальный шаблон. Свободный текст и числовые заявления LLM не отображаются: сервер формирует ответ сам. Реальный вызов Gemini без пользовательского ключа не проверялся; проверены отсутствие ключа, таймаут и невалидные ссылки.

## Границы MVP

1. Модель учебная: буферы не ограничены, транспорт нулевой, остальные детали доступны, нет переналадки и ограничения сроков заказов. Все VIN проходят контроль; брак и ремонт не моделируются.
2. Последние 200 снимков сохраняются в SQLite и доступны после перезапуска; последние 64 также кешируются в памяти. Путь задаётся `VIN_STATE_PATH`, по умолчанию `backend/data/runtime/snapshots.sqlite3`. Docker использует отдельный volume. Старые вытесненные снимки нужно пересчитать; демонстрационный запуск использует один worker.
3. Импорт меняет набор текущего расчёта; после перезагрузки страницы возвращается исходный демо-набор. Изменённые сценарии не сохраняются в БД. Отчёты можно скачать.
4. Импорт поддерживает согласованный JSON-формат с 80 эталонными VIN и маршрутом 0…5; произвольный завод, CSV и неизвестные BOM не поддерживаются.
5. Аутентификация и промышленная интеграция не входят в заданное ядро. Не открывайте этот демо-сервис как производственный диспетчерский API.
6. Эффект относится к текущей смене и не доказывает прибыль предприятия. Нет обученной модели предиктивного обслуживания.
7. Публичный хостинг не выполнен. Среда предпросмотра не поддерживает этот Python-backend; используйте локальный запуск или собственный хост с Node и Python. Репозитории GitHub не изменены, поскольку целевой репозиторий VIN-Twin не указан.

## Демонстрация на три минуты

- **0:00–0:30:** обзор штатной смены: мощность 80, прогноз 75, факт к 10:00. Объяснить демонстрационные допущения.
- **0:30–1:10:** выбрать «Задержка поставки». Прогноз 63. Переместить ползунок на 13:00: сборка-1 ждёт A, ETA 14:10. Открыть пост и VIN-049.
- **1:10–2:00:** открыть «Сценарии». Сравнить 63/71/69 и эффект 0/4,82/3,81 млн ₸. Применить доставку.
- **2:00–2:30:** выбрать «Оба сбоя». Обе платные политики дают 68; перестановка дешевле и становится рекомендацией.
- **2:30–3:00:** открыть ИИ-диспетчер и отчёт. Показать ссылки на проверенные факты, оговорить ограничения и завершить сбросом политики.

## Исправления после экспертной проверки — модель 1.1.0

- Перестановка сохраняет позиции остальных VIN и отклоняется, если изменяемый VIN уже начал маршрут до времени решения.
- События упорядочиваются детерминированно; точный повтор ID идемпотентен, конфликтующий повтор отклоняется. ETA может быть раньше планового, начало отказа берётся из события.
- Причины ожидания используют фактический комплект A/B. Источник, время и тип инцидента выводятся из входных данных; ручной сценарий помечается как допущение.
- Применение политики через `basis_snapshot_id` сохраняет исходные данные и события, не добавляя задержку повторно.
- Чат отвечает по конкретному VIN, сравнивает предыдущий снимок через `previous_snapshot_id` и показывает чувствительность выбора к вкладу автомобиля.
- Таблица чувствительности и пороги равного эффекта считаются сервером. Числа демонстрационного кейса на главной экспортируются из движка (`scripts/export_reference.py`), проверка обнаруживает устаревший экспорт.
- `/api/simulate` дополнительно принимает `robot_start` (минуты от 08:00) и `eta_override` (абсолютный ETA); при полученных событиях приоритет имеют их значения.

Полный перечень выполненных проверок и границ подтверждения — в `VERIFICATION.md`.

## Официальный кейс АЛЛЮР и дополнительные данные

Соответствие требованиям, архитектура, методика, потенциальный эффект и сценарий демонстрации — в `CASE_ALIGNMENT.md`. Исходные таблицы сохранены в `backend/data/factory-case.json`.

API: `GET /api/factory/data`, `POST /api/factory/analyze`, `POST /api/factory/chat`. Анализ принимает `scope` (unknown/shift/day), `workdays` (1–31), словарь `ideal_cycle_minutes` по участкам и сценарную `target_reject_percent`. Статический набор всегда остаётся исходными тестовыми данными; параметры изменяют только сценарий анализа.

Период строк по умолчанию неизвестен: месячная экстраполяция и OEE без обязательных входов не выдаются. Загрузка не подменяет OEE; дефекты последовательных участков не суммируются как уникальные автомобили. Полнота журнала и финальный складской выпуск не подтверждены. Объяснения агрегатной панели основаны на правилах и Python-расчётах, работают без внешнего сервиса.

Установщик использует отдельный `.npm-cache` внутри проекта, обходя старый кеш npm с чужими правами. Для запуска без Homebrew можно установить Python 3.12 официальным установщиком python.org, затем запустить `bash scripts/install.sh`; нужно, чтобы `python3.12` находился в PATH, или указать `VIN_PYTHON`. Homebrew не является зависимостью приложения.

## Настройка Gemini

Для необязательного Gemini в VIN-диспетчере выполните из корня:

```bash
bash scripts/configure-gemini.sh
bash scripts/dev.sh
```

Ключ вводится скрыто и сохраняется только в локальном `.env`, исключённом из Git. Gemini выбирает тип ответа по проверенным фактам; производственные расчёты остаются на сервере. При недоступности API используется локальное объяснение. Диспетчер аналитики кейса `/factory` работает на локальных правилах. Не публикуйте `.env` и ключи в коде, презентации или логах.
