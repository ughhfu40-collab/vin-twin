# VIN-Twin — цифровой двойник завода

**Решение кейса №2 АЛЛЮР:** аналитика производственных данных и интерактивная симуляция выпуска автомобилей.

VIN-Twin помогает увидеть потери качества, простои оборудования и разрыв производственного плана, а затем сравнить последствия решений диспетчера. Главная страница описывает проект; рабочие инструменты разделены по вкладкам.

> Учебный MVP. Таблицы за 1–2 октября 2026 года — тестовые данные кейса. VIN, комплекты деталей и события симуляции — синтетические. Подключения к реальному заводу, MES/WMS и управления оборудованием нет.

## Что установить

- **Python 3.12** — именно ветку 3.12. Установщик проекта проверяет версию; Python 3.14 для зафиксированных зависимостей не подходит.
- **Node.js 22 или новее** и npm. Для воспроизводимого запуска можно выбрать Node.js 22 LTS.
- Интернет нужен при первой установке зависимостей. Затем локальные расчёты и объяснения работают без внешнего API.

Официальные загрузки: [Python 3.12.10](https://www.python.org/downloads/release/python-31210/) — установщики Windows и macOS; [Node.js](https://nodejs.org/en/download) — выберите установщик для вашей системы. Python 3.12.10 — версия с готовыми установщиками; последующие выпуски ветки 3.12 содержат исправления безопасности.

**Без Git:** нажмите **Code → Download ZIP** на странице репозитория и распакуйте архив. Откройте терминал в распакованной папке проекта, где находятся `README.md`, `backend`, `frontend` и `scripts`.

Все команды ниже выполняются **из корня проекта**. Если папка называется `vin-twin-main` или `vin-twin 3`, используйте её фактическое имя; пути с пробелами заключайте в кавычки.

## Запуск на macOS

### 1. Установить Python и Node.js

Homebrew **не обязателен**. Установите Python 3.12 и Node.js через официальные установщики по ссылкам выше. После установки откройте новое окно Terminal.

Проверьте:

```bash
python3.12 --version
node --version
npm --version
```

Если Homebrew уже установлен, Python также можно установить командой `brew install python@3.12`. Если `brew` не найден, используйте официальный установщик.

### 2. Перейти в проект и установить зависимости

Пример для ZIP, распакованного в Downloads:

```bash
cd "$HOME/Downloads/vin-twin-main"
bash scripts/install.sh
```

Если Python установлен через официальный macOS-установщик, но команда `python3.12` не найдена:

```bash
VIN_PYTHON=/Library/Frameworks/Python.framework/Versions/3.12/bin/python3.12 bash scripts/install.sh
```

Установщик создаёт `.venv`, устанавливает backend и frontend. Несовместимую старую `.venv` сохраняет в резервной папке.

### 3. Запустить

```bash
bash scripts/dev.sh
```

Когда оба сервера запустятся, откройте **http://localhost:3000**. Оставьте терминал открытым; **Ctrl+C** останавливает приложение.

### Повторный запуск на Mac

Заново устанавливать зависимости при каждом запуске не нужно:

```bash
cd "$HOME/Downloads/vin-twin-main"
bash scripts/dev.sh
```

## Запуск на Windows

Используйте **PowerShell**, а не командную строку CMD. Bash и Homebrew не нужны.

### 1. Установить Python и Node.js

Установите Python 3.12 и Node.js через официальные установщики. Если установщик Python предлагает добавить Python в PATH, включите эту опцию. Откройте новое окно PowerShell.

Проверьте:

```powershell
py -3.12 --version
node --version
npm --version
```

### 2. Перейти в проект и установить зависимости

Пример для ZIP в Downloads:

```powershell
Set-Location "$HOME\Downloads\vin-twin-main"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
npm ci --prefix frontend --cache .npm-cache --no-audit --no-fund
```

Если команды `py` нет, но `python --version` показывает **3.12**, замените первую команду установки окружения на:

```powershell
python -m venv .venv
```

Активировать окружение через `Activate.ps1` не требуется.

### 3. Запустить

```powershell
npm run dev
```

Эта команда из корня запускает Python-backend и Next.js вместе. Откройте **http://localhost:3000**. Оставьте PowerShell открытым; **Ctrl+C** останавливает приложение.

### Повторный запуск на Windows

```powershell
Set-Location "$HOME\Downloads\vin-twin-main"
npm run dev
```

## Как показать решение

1. На главной кратко представьте проект и откройте **«Аналитика завода»**.
2. Покажите качество окраски и разрыв месячного плана. Вкладка **«Данные»** содержит исходные таблицы.
3. Во вкладке **«План и OEE»** уточните период строки, рабочие дни и идеальный цикл. Укажите также перерывы, когда производство не планировалось. Без обязательных входов OEE не отображается; несовместимые времена блокируют результат.
4. Откройте **VIN-симуляцию** и выберите задержку поставки.
5. Сравните FIFO, доставку и перестановку, изучите затронутый VIN.
6. Откройте диспетчер и сохраните отчёт. Отделяйте результаты учебной модели от подтверждённых показателей предприятия.

## Данные и контрольные результаты

Для аналитики используются:
- Работа трёх линий за 1–2 октября 2026 года.
- Журнал четырёх простоев оборудования.
- Месячный план: Onix 2500, Cobalt 1800, JAC J7 500.
- Выпуск и дефекты по участкам.
- Цели: OEE ≥85%, брак ≤2%, простой критического оборудования ≤60 минут в сутки, месячный выпуск ≥5500.

Сумма плана по моделям — **4800**, разрыв до цели — **700 автомобилей**. На сборке обработано **240**, годных до финального контроля — **237**. Взвешенная доля брака окраски — **4,33%**.

Дефекты последовательных участков не складываются как уникальные дефектные автомобили. Загрузка не подменяет OEE. Плановое время учитывает заданные перерывы; результат остаётся сценарным до подтверждения входов. Неизвестный период строки не превращается в фактический месячный прогноз. Для известного периода показаны средний сценарий и чувствительность к минимальному/максимальному темпу наблюдаемых дней, без статистического доверительного интервала.

**Отдельная VIN-модель:** смена 08:00–16:00, 80 VIN, шесть ресурсов по 6 минут, пустая линия в начале смены. Штатный выпуск и план — 75 автомобилей.

| Условия симуляции | FIFO | Доставка | Перестановка |
| --- | ---: | ---: | ---: |
| Штатная смена | 75 | 75 | 75 |
| Поставка +100 минут | 63 | 71 | 69 |
| Отказ робота на 40 минут | 68 | 68 | 68 |
| Оба сбоя | 63 | 68 | 68 |

«Спасено» = выпуск с действием − FIFO при тех же сбоях. Условный эффект = спасено × вклад автомобиля − затраты на действие. Это сценарная оценка, не доказанная прибыль предприятия.

## Диспетчер: локальные ответы

Ответы строятся по готовым шаблонам с числами из текущего расчёта. Диспетчер распознаёт вопросы о причинах ожидания, затронутых VIN, действиях и экономике; неизвестные вопросы получают описание допущений модели.

Внешние сервисы и API-ключи не требуются. Панель завода также использует локальные правила. Чат не является свободным генеративным диалогом.

## Если что-то не запускается

| Ошибка | Что делать |
| --- | --- |
| `brew: command not found` | Homebrew не нужен: установите Python 3.12 официальным macOS-установщиком |
| `python3.12: command not found` на Mac | Используйте `VIN_PYTHON=/Library/Frameworks/Python.framework/Versions/3.12/bin/python3.12 bash scripts/install.sh` |
| `py` не найден на Windows | Проверьте установленный Python; используйте `python -m venv .venv`, только если версия 3.12 |
| `npm` не найден | Установите Node.js и откройте новый терминал |
| PowerShell блокирует `npm.ps1` | Используйте `npm.cmd` вместо `npm` в приведённых командах |
| `pydantic_core`, `pyo3-ffi` при Python 3.14 | Пересоздайте окружение на Python 3.12; на Mac это делает установщик проекта |
| `No module named uvicorn` | Установка backend не завершилась: повторите установку зависимостей |
| `EACCES` в кеше npm | Используйте отдельный кеш `.npm-cache`, как в командах выше; Mac-установщик делает это автоматически |
| Порт 3000 или 8000 занят | Остановите предыдущий запуск проекта через Ctrl+C в его терминале |
| Главная открылась, а аналитика показывает ошибку | Проверьте, что backend запущен; откройте `/api/health` и посмотрите ошибки в терминале |

Если на Windows уже есть окружение от другой версии Python, сохраните его и повторите установку:

```powershell
Rename-Item .venv (".venv-backup-" + (Get-Date -Format "yyyyMMdd-HHmmss"))
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
npm ci --prefix frontend --cache .npm-cache --no-audit --no-fund
npm run dev
```

## Дополнительные варианты запуска

### Production, локально

Сначала установите зависимости и соберите frontend:

```bash
npm run build --prefix frontend
```

В первом терминале из корня запустите backend:

macOS/Linux:
```bash
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Windows:
```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из корня:

```bash
npm start --prefix frontend
```

При ручном запуске задавайте переменные конфигурации в окружении backend: эти команды не загружают `.env` автоматически.

### Docker Compose

При установленном Docker с Compose:

```bash
docker compose up --build
```

Сайт: http://localhost:3000. Backend доступен через frontend, отдельный внешний порт не опубликован; снимки сохраняются в volume. Конфигурация Docker включена; запуск через Docker не проверен.

## Границы решения

- OEE требует периода учёта и идеальных циклов; без них числовое значение не выдаётся.
- Двух дней данных недостаточно для обученного ML-прогноза отказов. Правила подсвечивают риски и превышения.
- Синтетическая VIN-модель не моделирует брак, переналадки, транспорт и ограниченные буферы.
- Импорт поддерживает согласованный JSON-формат демо-модели; произвольный завод и CSV не поддерживаются.
- Аутентификация и промышленная интеграция не входят в MVP.
- Репозиторий содержит код; публичный работающий хостинг приложения не развёрнут.
