# Спецификация VIN-Twin

## Назначение

VIN-Twin — учебный прототип цифрового двойника производственного потока автомобильного завода для кейса №2 АЛЛЮР. Интерфейс на русском языке.

Решение объединяет два независимых режима:
- Аналитика предоставленных тестовых таблиц по производственным участкам.
- Детерминированная VIN-симуляция для сравнения последствий производственных сбоев и действий диспетчера.

Источники данных и сценарные допущения должны быть видимы пользователю. Синтетические VIN не представляются как реальные автомобили предприятия.

## Пользовательские сценарии

1. Ознакомление с проектом на главной странице.
2. Просмотр факта, плана, качества и простоев по данным кейса.
3. Выбор параметров рабочего календаря и расчёт сценарного выпуска.
4. Расчёт OEE после уточнения периода строки и идеального цикла.
5. Выбор задержки поставки или отказа оборудования в VIN-модели.
6. Просмотр затронутого VIN, комплектности, маршрута и ожидания.
7. Сравнение FIFO, срочной доставки и допустимой перестановки.
8. Получение объяснения по актуальному расчёту и сохранение отчёта.

## Аналитика кейса

Исходные данные: работа линий за 1–2 октября 2026 года, журнал простоев, производственный план по моделям, показатели качества и последовательность участков.

Поток: склад комплектующих, сварка, окраска, сборка, контроль качества, склад готовой продукции.

Целевые показатели:
- Две смены по восемь часов.
- OEE не ниже 85%.
- Доля брака не выше 2%.
- Простой критического оборудования не более 60 минут в сутки.
- Выпуск не менее 5500 автомобилей в месяц.

Расчёт качества использует суммарные дефекты и объём участка. Дефекты последовательных участков не складываются как уникальные дефектные автомобили. Лимит простоя оценивается по единице оборудования и дате.

Для месячной экстраполяции необходим период исходной строки: смена или сутки. Для OEE дополнительно необходим идеальный цикл каждого участка и плановое время с учётом периодов, когда производство не планировалось. Время работы выше планового делает результат недопустимым. Неизвестные входы не заменяются скрытыми значениями. Загрузка участка не является OEE. Несовместимый идеальный цикл отмечается как ошибка входных допущений.

## VIN-модель

Базовая смена длится 480 минут, с 08:00 до 16:00. В наборе 80 VIN, линия в начале смены пуста. Маршрут включает шесть последовательных ресурсов по шесть минут. Завершение ровно в 16:00 учитывается.

Демонстрационные условия:
- Материалы A и B расходуются однократно при начале сборки.
- Задержка изменяет ETA поставки.
- Отказ приостанавливает пересекающую его операцию; незапущенная операция ждёт восстановления.
- Доставка изменяет будущий приход той же партии.
- Перестановка допустима только до начала маршрута затронутых VIN и при разрешении во входных данных.
- Уже состоявшиеся события не меняются задним числом.

Эффект действия сравнивается с FIFO при одинаковых исходных сбоях. Условный денежный эффект равен дополнительному выпуску, умноженному на вклад автомобиля, за вычетом затрат действия. Он не является подтверждённой прибылью предприятия.

## Интерфейс

Главная содержит описание проекта и вкладки «О проекте», «Возможности», «Как работает».

Панель завода содержит обзор, качество, оборудование, план и OEE, диспетчер и исходные данные.

VIN-панель содержит временную шкалу, схему ресурсов, очереди, реестр VIN, сценарии, сравнение решений, диспетчер и отчёт.

Обязательные состояния: загрузка, ошибка сервера, пустой поиск, недоступное действие. Рабочие панели поддерживают тёмную и светлую тему. Управление интерфейсом доступно с клавиатуры; адаптивная компоновка сохраняет доступ к таблицам и вкладкам.

## Данные, API и объяснения

Backend выполняет производственные расчёты и проверку входов. Frontend отображает рассчитанные состояния и не реализует отдельную производственную модель.

API принимает только допустимые параметры и возвращает понятную ошибку для некорректного ввода. Повтор события с тем же ID идемпотентен; конфликтующие повторы отклоняются.

VIN-снимки сохраняются в SQLite. Чат и отчёт используют идентификатор актуального снимка. Устаревший ответ не должен заменять результат нового запроса.

Объяснения используют готовые шаблоны, локальную классификацию вопросов и проверенные факты текущего расчёта. Числа и итоговый текст формируются сервером. Внешние API и ключи не используются. Неизвестный вопрос получает описание допущений модели.

## Технологии и проверка

Backend: Python 3.12, FastAPI, Pydantic, SQLite, httpx.
Frontend: Next.js, React, TypeScript, Tailwind CSS, SVG.

Зависимости зафиксированы. Документация содержит отдельные инструкции Windows и macOS и устранение ошибок установки.

Автоматические проверки охватывают эталонный выпуск, временные границы, последовательность операций, остатки материалов, доступность действий, события, экономику, объяснения и согласованность отчётов. Аналитика кейса проверяется на контрольных значениях и обязательных входах OEE.

## Границы MVP

Промышленные интеграции, телеметрия реального завода, аутентификация, статистически обученный прогноз отказов и подтверждение бизнес-эффекта не входят в MVP.

VIN-модель не учитывает брак, ремонт, транспорт, переналадки и ограниченные буферы. Импорт поддерживает согласованный демонстрационный JSON-формат. Двух дней данных недостаточно для достоверного обучения модели отказов. Диапазон месячных сценариев по наблюдаемому темпу не является доверительным интервалом. Исходные таблицы проходят арифметическую проверку согласованности.
