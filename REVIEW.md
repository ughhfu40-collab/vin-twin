# Исследовательская оценка VIN-Twin

Дата: 07.10.2026. Объект: реализация проекта и тестовые таблицы кейса №2 АЛЛЮР. Оценка основана на коде, контрольных расчётах и проверках интерфейса; интервью с производством и измерения на заводе не проводились.

## Вывод

Проект представляет собой воспроизводимый учебный MVP для демонстрации аналитики и сравнения производственных сценариев. Его сильная сторона — прозрачные расчёты с явными допущениями. Для промышленного пилота нужны подробные операционные данные, калибровка модели и контроль доступа.

## Сильные стороны

| Критерий | Подтверждение |
| --- | --- |
| Соответствие кейсу | Участки, оборудование, качество, простой, месячный план, OEE и сценарии решений представлены в интерфейсе |
| Проверяемые расчёты | Контрольные значения: план 4800/5500, разрыв 700; сборка 240/237; брак окраски 10/231 |
| Разделение происхождения данных | Историческая аналитика и синтетическая VIN-модель используют разные входы и явно обозначены |
| Воспроизводимость | Зафиксированные зависимости, детерминированный движок, инструкции Windows и macOS |
| Сравнение решений | Доставка, перестановка и FIFO сравниваются при одинаковых сбоях; стоимость действий учитывается |
| Прослеживаемость | VIN-паспорт, снимки расчётов, объяснения и отчёт используют согласованные данные |
| Автономность | Локальные шаблонные ответы, работа без внешнего сервиса после установки |
| Интерфейс | Отдельная главная, вкладки, темы рабочих панелей, поиск, фильтры и скачивание отчётов |
| Проверки | Backend-тесты, проверка типов, production-сборка и запросы через интерфейсный origin |

## Подтверждённые недостатки и исправления

| Недостаток | Изменение |
| --- | --- |
| Часть целей была зашита в расчётах | Пороги качества, OEE, простой, выпуск и сменность читаются из набора кейса |
| Плановое время OEE не позволяло исключить перерывы | Добавлен ввод перерывов вне плана на смену |
| Некорректное время могло дать доступность выше 100% | OEE и месячная экстраполяция блокируются с отдельным пояснением; значение не обрезается |
| Таблицы принимались без проверки связей | Проверяются уникальность, соответствие производства и качества, объёмы, время и доли |
| Неизвестный вопрос приводил к ответу о браке | Добавлена справка о поддерживаемых вопросах; пустые вопросы отклоняются |
| Параметры могли быть неприменены при переходе к чату | Общая отметка предыдущего расчёта и запрет запроса во время пересчёта; устаревшие ответы блокируются |
| Месячный сценарий давал только среднее | Добавлен диапазон при темпе каждого наблюдаемого дня; он не называется доверительным интервалом |
| Термин «достоверный OEE» преувеличивал подтверждение | Используется «сценарный OEE» с явными входами |
| Нулевой годный выпуск мог приводить к делению на ноль | Выводится недостижимость цели при текущем темпе вместо даты завершения |
| План выше цели мог давать отрицательный дефицит | Дефицит ограничен нулём, запас плана выделен отдельно |
| Сообщение установки предполагало Homebrew | Указан официальный установщик Python; Homebrew остаётся необязательным |

## Что остаётся ограничением

| Ограничение | Почему важно | Что нужно для пилота |
| --- | --- | --- |
| Всего два дня агрегатов | Нет доказанной сезонности, распределения отклонений и прогноза отказов | История нескольких производственных циклов с достаточным числом остановок; проверка на отложенном периоде |
| Неизвестен период строки | Суточный и сменный сценарии дают разные объёмы | Идентификатор смены, рабочий календарь и регламент времени |
| Нет VIN-связей между участками | Нельзя установить пересечение брака и реальное узкое место | VIN/WIP, начало и конец операций, межоперационные запасы |
| Нет финального складского выпуска | 237 годных на сборке не подтверждают 237 выпущенных автомобилей | Финальный контроль и приёмка склада |
| Журнал простоев неполный | Сумма записей не равна простою завода; интервалы могут пересекаться | Время событий, критичность, полный журнал оборудования |
| VIN-модель упрощена | Нет переналадок, ремонта, транспорта и ограниченных буферов | Проверка с технологом, измеренные времена и калибровка маршрута |
| Экономические значения сценарные | Вклад и стоимость действий не доказывают прибыль предприятия | Подтверждённые затраты, эффект пилота и контрольная база сравнения |
| Диспетчер ограничен шаблонами | Произвольный диалог не поддерживается | Расширять поддерживаемые темы по задачам пользователей |
| Нет промышленной авторизации | MVP рассчитан на демонстрацию | Учётные записи, роли, журнал действий и защищённое развёртывание |
| Нет публичного хостинга и нативного прогона всех систем | README не равен подтверждению работы на любом устройстве | Проверка на целевых Mac/Windows и выбранном хосте; Docker также требует отдельного запуска |

Эти ограничения нельзя устранить достоверно, придумав недостающие заводские данные. Они обозначены в интерфейсе и документации.

## Интерпретация чисел

При допущении «строка = одна смена» и 22 рабочих днях средний сценарий сборки составляет 5280 обработанных и 5214 годных до финального контроля. Повтор темпа отдельных наблюдаемых дней даёт 5236–5324 обработанных и 5148–5280 годных. Это сценарная чувствительность, а не диапазон вероятности будущего выпуска.

OEE рассчитывается как доступность × производительность × качество. Плановое время исключает периоды, когда производство не планировалось; остановки во время планового производства учитываются как потери доступности. Введённые циклы, перерывы и период требуют подтверждения. [Методика Vorne / OEE.com](https://www.oee.com/calculating-oee/).

## Критерии успешного пилота

1. Согласовать определения выпуска, брака, OEE, планового времени и простоя.
2. Сопоставить расчёт с контрольными данными технолога и документировать расхождения.
3. Проверить сценарные решения на реальных ограничениях; не менять прошлые события.
4. Измерить результат на отдельном периоде и сравнить с согласованной базой.
5. До операционного использования проверить роли, журнал действий, сохранность данных и работу на целевых устройствах.
