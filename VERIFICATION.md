# Результаты проверки

Дата: 06.10.2026. Python 3.12.14, Node.js 24.19.0, Next.js 15.5.26. Модель 1.1.0.

## Автоматические проверки

- `bash scripts/check.sh`: 43 теста Python, TypeScript и production-сборка. Одно предупреждение Starlette об устаревшем alias BlockingPortal; на результат не влияет.
- `scripts/export_reference.py --check`: числа кейса на главной соответствуют текущему движку.
- `scripts/integration_check.py`: реальные Uvicorn и production Next.js в одной сетевой среде, запросы через общий origin. Проверены главная, дашборд, health/state/simulate/chat/report, 12 эталонных выпусков, эффект доставки 4 820 000 ₸, согласованность снимков и ошибка 422 на некорректный ввод.
- Регрессии: сохранение прошлого при нестандартной очереди, поздние действия, начало отказа из события, ранний ETA/получение партии, материал B, источники и типы инцидентов, повторные и конфликтующие ID, порядок событий, сравнение снимков, конкретный VIN, чувствительность экономики и применение/сброс политики без повторного изменения ETA.
- Сохранение снимка в SQLite подтверждено после очистки кеша процесса: отчёт, чат и действие остаются доступны. Перезапуск ОС и исчерпание диска не моделировались.
- Gemini fallback проверен без ключа, при таймауте и невалидных fact_id; непроверенный свободный текст провайдера не используется как ответ с числами.

## Браузерная проверка

Использован настоящий frontend и настоящий FastAPI TestClient. Из-за изоляции сетевых сред запросы временно передавались через файловый транспорт; ответы рассчитывал тот же backend. Транспорт и тестовая страница удалены из итогового проекта. Финальная HTTP-проверка использует штатный proxy Next.js без этого транспорта.

Подтверждено в браузере:

- Главная страница, описание проекта, переходы к демонстрации.
- Задержка: прогноз 63, сравнение 63/71/69, применение доставки: 71 и эффект 4 820 000 ₸.
- Поиск VIN-049, открытие маршрута и ответ чата о конкретном ожидании после применения доставки: 13:00–13:20, завершение 13:44.
- Два сбоя: 63/68/68, объяснение смены рекомендации с доставки на перестановку и сравнение эффектов.
- Таблица чувствительности и пороги равного эффекта, включая 145 000 ₸ для доставки/перестановки при задержке.
- Отчёт содержит тот же снимок, источники событий, сравнение решений и чувствительность; TXT скачивается.
- Копирование в HTTP-предпросмотре ограничено разрешениями браузера: отображается корректное сообщение и доступно скачивание. Успешное копирование на localhost/HTTPS отдельно не подтверждено.
- Применение и сброс доставки: прогноз возвращается к 63.
- Воспроизведение получения событий: ETA помечен как факт с источником демо-логистики, условие робота — как сценарное допущение.
- В доступных логах после исправлений ошибок приложения не найдено; отдельно присутствовали ошибки служебного расширения браузера.
- Переключение тёмной/светлой темы. Узкая компоновка проверена в iframe шириной 390 px (375 px без полосы прокрутки): ширина содержимого равна ширине области, горизонтального переполнения нет. Это проверка адаптивной компоновки, не тест на физическом телефоне.

В браузере обнаружена и исправлена ошибка готовых сценариев: в строгий API передавалось лишнее поле имени пресета. Теперь сериализуются только допустимые параметры запроса.

## Исправление установки на macOS / Python 3.14

По присланному журналу установка использовала CPython 3.14 на Apple Silicon; сборка pydantic_core 2.33.2 остановилась из-за ограничения PyO3, затем запуск завершился отсутствием uvicorn.

Установщик теперь явно выбирает Python 3.12 (или VIN_PYTHON), проверяет версию до установки, сохраняет несовместимую .venv в резервном каталоге и создаёт новую. Оба способа запуска проверяют версию и наличие backend-зависимостей до старта серверов. Добавлены четыре проверки запуска/установки: неверная версия, сохранение старой среды, отказ shell- и Node-запуска при неполной установке.

Всего: 47 тестов Python. Проверки bash -n и node --check также прошли. Новые сценарии установки проверены изолированно с подменёнными командами; установка на физическом Mac пользователя не запускалась. Production-код frontend и API не менялся, предыдущая проверка сборки относится к тем же исходникам приложения.

## Дополнительные данные и официальный кейс АЛЛЮР

Добавлен независимый модуль агрегатной аналитики `/factory`, исходные тестовые данные организаторов, калькулятор OEE с явными входами, сценарии календаря и предотвращения брака, локальные объяснения и выгрузка отчёта/JSON. Сопоставление с требованиями PDF — `CASE_ALIGNMENT.md`.

Общий набор: 58 тестов Python. Новые проверки подтверждают 4800/700 модельного плана, 240/237 на сборке, взвешенный брак окраски 10/231, минимум шесть предотвращённых дефектов для 2%, три строки превышения, дневной лимит по единице оборудования, зависимость сценария от периода строк и проверку идеального цикла. Формула OEE сверена с методом oee.com.

В браузере на настоящем FastAPI TestClient через временный файловый транспорт подтверждены: показатели панели, выбор смены и 22 дней (5280/5214), P >100% при несовместимом цикле 4 минуты, цель брака 1% (восемь дефектов окраски), объяснение модельного плана, переход со схемы к фильтру Камеры-02, скачивание TXT и исходного JSON, тёмная/светлая темы. В iframe 390 px содержимое занимает 375 px без полосы прокрутки, горизонтального переполнения документа нет; вкладки и таблицы имеют локальную прокрутку. Ошибок приложения в доступной консоли не обнаружено.

Временные маршруты и транспорт удалены перед финальной сборкой. HTTP-проверка расширена на `/factory` и все три её API с обычным Next.js proxy. Реальная телеметрия, обученный прогноз отказов и промышленная валидация не заявлены.
